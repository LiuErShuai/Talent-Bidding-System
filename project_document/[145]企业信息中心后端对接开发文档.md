# [101] 企业信息中心后端对接开发文档

---

## 1. 功能概述
企业信息中心（路由 `/enterprise/profile`）用于展示与管理企业的基础资料、资质信息以及认证状态。前端需要完成以下几类交互：

1. **查看企业完整资料**（包括企业扩展字段）
2. **编辑可自由修改的非核心字段**（公司简介、标签、官网、地区）
3. **上传资质文件**（图片、PDF）
4. **提交企业认证（核心字段）**
5. **查询当前认证状态及驳回原因**

所有接口均基于 **JWT Token** 鉴权，需在请求头 `Authorization: Bearer <token>` 中携带。

## 2. API 列表（来源：《[002]API文档.md》）
| 编号 | 接口描述 | 方法 | 路径 | 请求体 / 参数 | 响应关键字段 | 备注 |
|------|----------|------|------|--------------|--------------|------|
| 1 | 查看企业完整资料 | GET | `/api/v1/user_management/profile/{userId}` | `userId`（路径） | `companyIntro、companyTags、creditCode、companyIndustry、companyScale、companyRegion、companyWebsite、contactPerson、contactPosition、contactPhone、contactEmail、qualificationFiles` | 需要 JWT，返回企业扩展字段 |
| 2 | 编辑非核心字段 | POST | `/api/v1/user_management/company/update_profile` | `{ companyIntro?, companyTags?, companyWebsite?, companyRegion? }` | `data: true` | 只能修改非核心字段，核心字段（如信用代码）受锁定 |
| 3 | 上传资质文件 | POST | `/api/v1/user_management/company/upload_qualification` | `multipart/form-data`（`file` 必填） | `data: "/static/qualifications/xxxx/xxx.jpg"` | 返回文件可访问 URL |
| 4 | 提交企业认证（核心字段） | POST | `/api/v1/user_management/company/submit_qualification` | `{ creditCode, companyIndustry, companyScale, contactPerson, contactPosition?, contactPhone, contactEmail?, fileUrls[] }` | `data: true` | 提交后状态变 `pending_review`，核心字段一旦认证成功即被锁定（除非重新提交） |
| 5 | 查询待审核企业列表（管理员） | GET | `/api/v1/user_management/admin/company/pending_review` | `status=pending_review`（可选），`page`，`pageSize` | 企业列表 + `certificationStatus`、`rejectReason`、`submitTime` | 仅管理员权限 |
| 6 | 管理员通过/拒绝认证 | POST | `/api/v1/user_management/admin/company/approve/{userId}` <br> `/api/v1/user_management/admin/company/reject/{userId}` | `userId`（路径）<br>`{ reason }`（拒绝） | `data: true` | 同上 |

## 3. 前端调用示例（基于已有 `src/api/request.js`）
```js
// src/api/enterprise.js
import request from '@/api/request'

/** 1. 获取企业完整信息 */
export function getEnterpriseProfile(userId) {
  return request.get(`/api/v1/user_management/profile/${userId}`)
}

/** 2. 更新非核心信息 */
export function updateEnterpriseProfile(data) {
  return request.post('/api/v1/user_management/company/update_profile', data)
}

/** 3. 上传资质文件 */
export function uploadQualification(file) {
  const form = new FormData()
  form.append('file', file)
  return request.post('/api/v1/user_management/company/upload_qualification', form, {
    headers: { 'Content-Type': 'multipart/form-data' }
  })
}

/** 4. 提交企业认证（核心字段） */
export function submitEnterpriseQualification(data) {
  return request.post('/api/v1/user_management/company/submit_qualification', data)
}
```

> **使用说明**
> - 在页面 `src/views/enterprise/Profile/index.vue` 中，通过 `useAuthStore()` 获取当前登录用户的 `userId`。
> - 页面加载时调用 `getEnterpriseProfile(userId)`，将返回的 `qualificationFiles` 渲染为文件列表，`certificationStatus` 用于展示审核进度。
> - 表单提交时，仅把实际变更的字段放入 `updateEnterpriseProfile`，避免覆盖锁定字段。
> - 资质文件上传成功后，把返回的 URL 收集到数组 `fileUrls`，在 **提交认证** 时一并提交。

## 4. 数据模型（前端 TypeScript）
```ts
/** 企业完整信息（profile 接口返回） */
export interface EnterpriseProfile {
  userId: string;
  type: 2;
  nickname: string;
  avatarUrl?: string;
  // 非核心可编辑字段
  companyIntro?: string;
  companyTags?: string[];
  companyWebsite?: string;
  companyRegion?: string;
  // 核心字段（认证后锁定）
  creditCode?: string;
  companyIndustry?: string;
  companyScale?: string;
  contactPerson?: string;
  contactPosition?: string;
  contactPhone?: string;
  contactEmail?: string;
  // 资质文件 URL 列表
  qualificationFiles?: string[];
  // 认证状态（后端在 profile 中返回，可自行扩展）
  certificationStatus?: 'uncertified' | 'pending_review' | 'certified' | 'rejected';
  rejectReason?: string;
}
```

## 5. 前端页面交互流程
1. **页面初始化**
   - `onMounted` → 调用 `getEnterpriseProfile(userId)` → 存入 Pinia `enterpriseStore`。
2. **编辑非核心信息**
   - UI 使用 Element Plus `el-form`，提交时调用 `updateEnterpriseProfile(updateData)`。
3. **上传资质文件**
   - 使用 `<el-upload>`，`onSuccess` 将返回 URL push 到 `fileUrls` 数组。
4. **提交认证**
   - 收集核心字段（信用代码、行业、规模、联系人信息）+ `fileUrls` → `submitEnterpriseQualification(payload)`。
   - 成功后弹出 “提交成功，待审核”，并将页面状态切换为 `pending_review`（不可再次编辑核心字段）。
5. **查询认证状态**
   - `certificationStatus` 随 `profile` 返回，如为 `rejected`，在页面展示 `rejectReason` 并显示 “重新提交” 按钮。

## 6. 错误码约定与处理
| 错误码 | 场景 | 处理建议 |
|--------|------|----------|
| `0002` | 参数非法（缺少必填字段或文件大小超限） | 前端表单校验，弹出用户友好提示 |
| `0006` | Token 无效或过期 | 自动跳转登录页或弹窗提醒重新登录 |
| `0003` | 用户不存在（userId 错误） | 显示 “企业信息未找到”，提供返回首页按钮 |
| `BID003` | 权限不足（非企业用户） | 隐藏编辑入口，提示 “仅企业账号可操作” |

## 7. 安全注意事项
- 所有上传文件仅接受 **图片 / PDF**，后端已做文件类型校验，前端在 `beforeUpload` 中再次限制。
- 核心字段在提交认证后会被锁定，前端必须在 UI 上做只读展示，防止误提交。
- 在 `submitEnterpriseQualification` 前，请确保 **已完成文件上传**，否则后端会返回 `0002`。
- 对于 **敏感信息**（如统一社会信用代码），仅在页面展示时做脱敏处理（如只显示前四位 + `****`），该脱敏逻辑在前端实现。

## 8. 测试建议（手动/自动）
1. **获取企业信息**：使用已登录企业账号，确认返回的 `qualificationFiles`、`certificationStatus` 正确。
2. **更新非核心字段**：修改 `companyIntro`、`companyTags`、`companyWebsite`、`companyRegion`，提交后再次读取确认已生效。
3. **上传资质文件**：分别上传图片、PDF，检查返回的 URL 能在页面预览并加入 `fileUrls`。
4. **提交认证**：在未填写核心字段或缺少 `fileUrls` 时，接口应返回 `0002`。
5. **认证状态流转**：提交后状态变 `pending_review`，管理员通过或拒绝后，重新拉取 `profile`，页面应展示 `certified` 或 `rejected`（并显示 `rejectReason`）。
6. **异常场景**：Token 失效、用户被锁定、文件超限等，确保前端能够捕获并展示统一的错误弹窗。
