## 二、页面入口与布局

页面采用左右两栏布局，侧边栏顶部有"发布项目"按钮。点击后主内容区切换为三步发布表单。

```
┌──────────────────────────────────────────────┐
│  侧边栏(240px)  │       主内容区(flex:1)       │
│                  │                              │
│  [+ 发布项目] ◄──┼── 点击后切换到发布表单        │
│                  │                              │
│  我的项目        │  ┌────────────────────────┐  │
│  ├ 我发布的(N)   │  │  el-steps 步骤条        │  │
│                  │  │  基本信息→里程碑→确认   │  │
│                  │  │                        │  │
│                  │  │  当前步骤的表单内容      │  │
│                  │  └────────────────────────┘  │
└──────────────────────────────────────────────┘
```

通过 `activeTab` ref 控制视图切换：
- 点击"发布项目"按钮 → `activeTab = 'publish'`，显示三步表单
- 取消或提交成功 → `activeTab = 'published'`，回到项目列表

步骤条使用 Element Plus 的 `el-steps` 组件，通过 `currentStep`（0/1/2）控制当前步骤，三个步骤面板用 `v-show` 切换显示。

## 三、步骤一：基本信息

### 3.1 表单字段

| 字段 | 组件 | 验证规则 | 说明 |
|------|------|---------|------|
| 项目名称 `name` | el-input | 必填，5-50字符 | maxlength=50，显示字数统计 |
| 项目领域 `category` | el-select | 必填 | 8个固定选项（人工智能/大数据/云计算/物联网/区块链/移动开发/Web开发/其他） |
| 悬赏金额 `reward` | el-input-number | 必填，最低1000 | 范围1000-1000000，步长1000，默认5000 |
| 需求人数 `teamSize` | el-input | 必填 | 自由文本，如"2-4人" |
| 项目周期 `duration` | el-input-number | 必填，7-365天 | 默认60天，变更时自动计算交付时间 |
| 揭榜截止时间 `deadline` | el-date-picker | 必填 | 禁选过去日期，变更时自动计算交付时间 |
| 预计交付时间 `deliveryDate` | el-date-picker | — | 自动计算（截止时间 + 项目周期天数），disabled 不可编辑 |
| 项目详情 `description` | el-input(textarea) | 必填，至少100字符 | 12行，maxlength=5000，placeholder 提供详细填写引导 |
| 任务文件 `taskFiles` | el-upload | — | 最多5个文件，单个不超过50MB |
| 最小团队人数 `minTeamSize` | el-input-number | — | 范围2-10，默认2 |
| 最大团队人数 `maxTeamSize` | el-input-number | — | 范围min~20，默认4 |
| 项目要求 `projectRequirements` | el-input(textarea) | — | 4行，maxlength=500 |
| 最大申请数 `maxApplications` | el-input-number | — | 范围1-100，默认20 |

### 3.2 表单分区

表单分为三个区块，用分割线（`border-bottom`）隔开，每个区块有蓝色左边框标题：

1. **项目基本信息** — 名称、领域、金额、人数、周期、截止时间、交付时间
2. **项目详情** — 描述 textarea + 任务文件上传
3. **揭榜要求** — 团队规模范围、项目要求、最大申请数

### 3.3 交付时间自动计算

当 `deadline` 或 `duration` 变更时触发 `calculateDeliveryDate()`：

```javascript
deliveryDate = new Date(deadline.getTime() + duration * 24 * 60 * 60 * 1000)
```

`deliveryDate` 字段设为 `disabled`，用户不可手动修改。

### 3.4 文件上传

- 上传地址：`http://localhost:8091/api/v1/upload`（硬编码）
- 文件大小限制：50MB（`beforeUpload` 钩子校验）
- 文件数量限制：5个（`limit` 属性 + `on-exceed` 提示）
- 支持多文件上传（`multiple`）
- 文件预览：标注了 `// TODO: 实现文件预览功能`，当前仅 console.log

## 四、步骤二：里程碑配置

### 4.1 预定义里程碑

预定义了 7 个里程碑节点，4 个必选、3 个可选：

| 序号 | 代码 | 名称 | 必选 | 默认启用 | 预设交付物 |
|------|------|------|------|---------|-----------|
| 1 | `proposal` | 方案提交 | 是 | 是 | 技术方案文档、项目计划甘特图 |
| 2 | `agreement` | 协议签订 | 是 | 是 | 项目合作协议 |
| 3 | `midterm` | 中期答辩 | 否 | 否 | 中期报告、演示视频 |
| 4 | `result_submit` | 成果提交 | 是 | 是 | 源代码、部署文档、用户手册 |
| 5 | `result_review` | 成果评审 | 否 | 否 | （无预设） |
| 6 | `settlement` | 项目结算 | 是 | 是 | 验收报告、发票 |
| 7 | `publicity` | 结项公示 | 否 | 否 | （无预设） |

每个里程碑的数据结构：

```javascript
{
  code: 'proposal',
  title: '方案提交',
  description: '提交详细的技术方案和项目实施计划...',
  required: true,       // 是否必选
  enabled: true,        // 是否启用
  expanded: false,      // 配置面板是否展开
  goal: '',             // 里程碑目标
  plannedDate: '',      // 计划完成时间
  taskFiles: [],        // 任务文件
  deliverables: [       // 交付物列表
    { name: '技术方案文档', format: 'PDF / Word', requirement: '不少于10页...' }
  ]
}
```

### 4.2 里程碑交互

每个里程碑以卡片形式展示，交互如下：

```
┌─────────────────────────────────────────────────┐
│ ☑ 方案提交  [必选]                    [展开配置] │  ← 头部：checkbox + 标题 + 标签 + 展开按钮
│ 提交详细的技术方案和项目实施计划...               │  ← 描述文本
│                                                 │
│ ┌─ 展开后的配置表单 ──────────────────────────┐ │
│ │ 里程碑目标：[textarea]                      │ │
│ │ 计划完成时间：[date-picker]                 │ │
│ │ 交付物要求：                                │ │
│ │   ┌ 交付物1 ─────────────────────────────┐ │ │
│ │   │ 名称：[input]  格式：[input]          │ │ │
│ │   │ 要求：[textarea]         [删除交付物] │ │ │
│ │   └──────────────────────────────────────┘ │ │
│ │   [+ 添加交付物]                           │ │
│ │ 任务文件：[el-upload] 最多3个，单个≤50MB    │ │
│ └────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────┘
```

- checkbox 控制启用/禁用，必选项的 checkbox 为 disabled 状态
- 禁用时自动收起配置面板，卡片整体变灰（`opacity: 0.6, background: #f5f5f5`）
- 启用后可点击"展开配置/收起"按钮切换配置面板
- 里程碑计划完成时间不能早于揭榜截止时间（`disabledMilestoneDate` 函数控制）

### 4.3 交付物管理

每个里程碑的交付物是动态列表，支持增删：

- **添加**：点击"+ 添加交付物"按钮，push 一个空对象 `{ name: '', format: '', requirement: '' }`
- **删除**：点击"删除交付物"按钮，splice 移除对应项
- 每个交付物包含三个字段：名称（input）、文件格式（input）、具体要求（textarea）
- 必选里程碑已预设了交付物数据，用户可在此基础上修改

## 六、步骤导航与提交逻辑

### 6.1 步骤切换

每个步骤底部有操作按钮：

| 步骤 | 左侧按钮 | 右侧按钮 |
|------|---------|---------|
| 步骤一 | 取消（重置表单，回到列表） | 下一步 |
| 步骤二 | 上一步 | 下一步 |
| 步骤三 | 上一步 | 提交发布 |

- "下一步"：直接 `currentStep++`，不做即时验证
- "上一步"：直接 `currentStep--`
- "取消"：调用 `publishFormRef.resetFields()` 重置表单，`currentStep = 0`，切回列表

### 6.2 提交验证流程

点击"提交发布"时触发 `handleSubmitPublish()`，执行以下验证：

```
1. 验证步骤一表单（el-form validate）
   ├─ 失败 → ElMessage.error('请完善项目基本信息')，跳回步骤一
   └─ 通过 ↓

2. 验证至少有一个启用的里程碑
   ├─ 失败 → ElMessage.error('请至少选择一个里程碑')，跳回步骤二
   └─ 通过 ↓

3. 遍历每个启用的里程碑，检查：
   ├─ goal 为空 → ElMessage.error('请配置"xxx"的里程碑目标')，跳回步骤二
   ├─ plannedDate 为空 → ElMessage.error('请设置"xxx"的计划完成时间')，跳回步骤二
   └─ 全部通过 ↓

4. 提交成功
   ├─ console.log 输出 { basicInfo, milestones }
   ├─ ElMessage.success('项目发布成功！')
   ├─ 重置表单，currentStep = 0
   └─ 切回已发布列表（activeTab = 'published'）
```

当前状态：提交逻辑只做了前端验证和 console.log，**尚未调用后端 API**（代码中标注了 `// TODO: 调用API提交项目`）。
